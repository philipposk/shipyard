# Verdict and answer

## Pick one

| Verdict | When |
|---|---|
| **Adopt** | One project covers all the must-haves, has a licence that fits, was pushed to in the last 18 months and has real code. Use it as it is. |
| **Extend** | One project covers most of it. Add the missing part on top (a plugin, a wrapper, a pull request, or a fork if the student says yes). |
| **Compose** | No single project fits, but two or three small ones each cover a piece. Glue them together. |
| **Build** | Nothing real covers it, or what exists is stale, unlicensed, prompt-only with no real logic, or against the student's must-haves. Build it, and borrow ideas. |

When unsure between two, choose the one that means less code for the student to keep alive.

## Answer shape

1. **Verdict** in one line, with the reason in plain words.
2. **Shortlist**, best first:

| Repo | Stars | Last push | Licence | Covers | Gaps |
|---|---|---|---|---|---|

3. **Why the runners-up lost**, one line each (stale, no licence, only covers a part, prompt-only).
4. **Queries that worked**, so the student can repeat or widen the search.
5. **Not verified**: no security scan was run, licences are from GitHub metadata, only GitHub (and the registries named) were searched, and anything the student's must-haves needed that you could not confirm from the README.

Keep it to one screen. Explain any new word in five words or fewer.

## Licences in one line

- MIT, Apache-2.0, BSD, ISC: fine to use, including commercially.
- GPL, AGPL: allowed, but code built on them may have to be shared under the same licence. Say so if the student sells the app.
- No licence, or "all rights reserved": reference only.

Ideas from a project without a licence may be used. Its code may not be copied.
