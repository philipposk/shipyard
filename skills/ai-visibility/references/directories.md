# Directories and listings, honestly

The goal is a few accurate, durable mentions that people and models trust, not volume.

## Rules
- Draft first, submit only with the student's yes for that place. Their account, their name.
- One honest description adapted to each place; never claim features the app does not have.
- No fake reviews, vote swaps, sock puppets, mass submission tools or paid "AI directory blasts".
- Respect each community's self-promotion rules (Reddit and Hacker News especially). Post as the maker, answer comments.
- Free listings first. Mention anything paid and its price before suggesting it.

## Priority (adjust to the app)
1. **The app's own GitHub repo** (if public): clear README first paragraph with the one-liner and live link, topics. Free, durable, read by models.
2. **Product Hunt**: one launch, Tuesday to Thursday, with a maker first comment telling why it exists.
3. **AlternativeTo**: list it as an alternative to the tools the baseline models recommended instead.
4. **Show HN** (only if it is genuinely interesting to developers) and **Indie Hackers**.
5. **Relevant subreddits** where self-promotion is allowed (for example r/SideProject), once.
6. **AI tool directories** if the app uses AI: There's An AI For That, Futurepedia, Toolify. **MCP directories** if it has an MCP server: mcp.so, Smithery, Glama, awesome-mcp-servers.
7. **Launch lists**: SaaSHub, Uneed, Microlaunch, BetaList, DevHunt (developer tools).
8. **Wikidata**: only when the app has independent coverage to cite (notability rules).

## Draft format (one block per place)
Place, link, what it needs (account, logo, screenshots), and the ready-to-paste text: name, tagline (60 characters), description (about 100 words), tags, pricing, the "alternative to" list.
